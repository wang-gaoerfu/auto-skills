## 十、Toonflow-app 对比分析（2026-03-15）

### 10.1 架构对比

| 维度 | Toonflow-app | 本设计 |
|------|--------------|--------|
| 提示词存储 | 数据库 (t_prompts) | 代码文件 |
| 多代理协作 | ✅ AI1/AI2/director | ❌ 单一提示词 |
| 工具调用 | ✅ 丰富工具集 | ❌ 纯文本生成 |
| 图片生成 | ✅ 集成 generateImageTool | ❌ P2 功能 |
| 动态可配置 | ✅ 运行时可修改 | ❌ 需要发版 |
| SSE 流式 | ❌ | ✅ |
| 独立会员 | ❌ | ✅ |
| 低成本 | ❌ | ✅ DeepSeek |

### 10.2 Toonflow-app 亮点（可借鉴）

1. **多代理协作机制**
   - AI1 (storyline) → 生成故事线
   - AI2 (outline) → 生成详细大纲
   - director → 审核并修正

2. **分镜两阶段处理**
   - segmentAgent → 拆分片段（情感、动作）
   - shotAgent → 生成具体镜头（含图片提示词）

3. **丰富的结构化输出**
   - openingHook, endingHook (钩子设计)
   - emotionalCurve (情感曲线)
   - visualHighlights (视觉高光)
   - classicQuotes (经典台词)

### 10.3 许可证风险

⚠️ **AGPL-3.0 限制**：
- 商业使用需开源整个应用
- 网络服务使用也触发开源义务
- 不能直接复用代码、提示词、数据结构

✅ **可借鉴（不涉及版权）**：
- 功能流程设计思路
- 用户交互模式
- 多代理架构理念

### 18.3 场景创建失败修复（2026-03-17）

**问题**：分析 API 在创建场景时报错 `Unknown argument 'characters'`

**原因**：
- `analyze/route.ts` 中尝试使用 `characters: { connect: characterIds }` 关联角色
- 但 Prisma Schema 中 `ScriptScene` 模型没有定义与 `ScriptCharacter` 的多对多关系
- 角色出场信息通过 `ScriptShot.characterIds` 字段存储

**解决方案**：
移除场景创建时的角色关联代码，角色信息在镜头生成阶段关联

**修改文件**：
```typescript
// src/app/api/scripts/[id]/analyze/route.ts
// 移除以下代码：
// const characterIds = scene.characters.map(...)
// ...(characterIds.length > 0 && { characters: { connect: characterIds } })
```
