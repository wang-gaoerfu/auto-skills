## 三、当前设计亮点

### 3.1 架构设计

| 亮点 | 说明 |
|------|------|
| **完全解耦** | 剧本系统与小说系统独立，数据不互通 |
| **零侵入集成** | 仅在项目列表增加一个"转剧本"按钮 |
| **独立会员** | 支持单独购买剧本权益，不绑定小说会员 |
| **流式生成** | SSE 实时反馈，用户体验好 |

### 3.2 功能设计

| 亮点 | 说明 |
|------|------|
| **多来源导入** | 自有项目/TXT上传/粘贴/从零创作 |
| **AI 预处理** | 智能分章+角色提取+场景提取 |
| **灵活编辑** | 手动编辑+AI辅助+分段重新生成 |
| **多格式导出** | JSON/MD/PDF/Excel |

### 3.3 技术设计

| 亮点 | 说明 |
|------|------|
| **完整的错误处理** | 超时/限流/违规/配额等场景都有处理策略 |
| **状态机设计** | 清晰的状态流转，避免逻辑混乱 |
| **恢复机制** | 生成中断后可恢复，数据不丢失 |
| **埋点统计** | 完整的事件定义，支持运营分析 |

## 四点五、Toonflow-app 对比分析

### 4.5.1 项目对比

| 对比项 | Toonflow-app | 本项目 |
|--------|--------------|--------|
| 定位 | 短剧全流程工具 | 剧本生成工具 |
| 许可证 | AGPL-3.0 ⚠️ | 商业项目 |
| 技术栈 | Express + Electron + SQLite | Next.js + Prisma + PostgreSQL |
| AI 成本 | 高（视频+图片生成） | 低（仅文本生成） |
| 独立会员 | ❌ | ✅ |
| SSE 流式 | ❌ | ✅ |

### 4.5.2 许可证风险

**AGPL-3.0 限制**：
- 商业使用需开源整个应用
- 网络服务使用也触发开源义务
- 不能直接复用代码、提示词、数据结构

**可借鉴（不涉及版权）**：
- 功能流程设计思路
- 用户交互模式
- 产品定位策略

### 4.5.3 结论

Toonflow-app 定位为全流程工具（含视频生成），与本项目差异化明显。且 AGPL-3.0 许可证限制商业使用，**不建议参考其具体实现**。本项目保持原创设计即可。
