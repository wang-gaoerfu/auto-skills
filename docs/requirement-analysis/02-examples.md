# 需求分析系统 - 使用示例

本章节提供多个真实场景的使用示例。

---

## 示例 1：电商网站

### 初始需求

```
我想做一个宠物用品电商平台，主要卖猫粮和狗粮。
```

### 完整对话

**Q1**: 目标用户是谁？有什么特色？

```
A: 目标用户是宠物主人，特色是兽医推荐和营养分析。
```

**Q2**: 核心功能有哪些？

```
A: 商品浏览、搜索、购物车、下单支付、用户注册登录。
```

**Q3**: 有技术栈偏好吗？

```
A: 希望用 Vue + Spring Boot。
```

### 输出要点

```markdown
=== 1) 需求概述 ===
• 需求名称: 宠物用品电商平台
• 一句话描述: 提供兽医推荐和营养分析的专业宠物用品平台

=== 4) 功能需求 ===
• 核心功能 (P0):
  1. 商品展示
  2. 搜索筛选
  3. 购物车
  4. 订单支付
  5. 用户系统

• 重要功能 (P1):
  1. 兽医推荐内容
  2. 营养分析工具
  3. 宠物档案管理

=== 6) 技术约束 ===
• 技术栈:
  • 前端: Vue
  • 后端: Spring Boot
  • 数据库: MySQL
```

## 示例 2：移动应用 - 健身追踪

### 初始需求

```
我想做一个健身追踪 App。
```

### 完整对话

**Q1**: 是原生还是跨平台？

```
A: 希望跨平台，React Native。
```

**Q2**: 主要功能是什么？

```
A: 运动记录、饮食记录、体重追踪、数据统计。
```

**Q3**: 需要离线功能吗？

```
A: 是的，需要离线记录运动数据。
```

### 输出要点

```markdown
=== 1) 需求概述 ===
• 需求类型: 移动应用
• 一句话描述: 跨平台健身追踪 App，支持运动和饮食记录

=== 4) 功能需求 ===
• 核心功能 (P0):
  1. 运动记录（跑步、健身等）
  2. 饮食记录
  3. 体重追踪
  4. 数据统计展示
  5. 离线数据存储

=== 7) 用户体验 ===
• 响应式需求:
  • iOS 14+
  • Android 8+
  • 平板适配

=== 5) 非功能需求 ===
• 性能要求:
  • App 启动 < 2s
  • 数据同步 < 5s
```

## 示例 3：API 服务 - 支付网关

### 初始需求

```
我们需要一个统一的支付网关 API。
```

### 完整对话

**Q1**: 需要对接哪些支付渠道？

```
A: 微信支付、支付宝、银联。
```

**Q2**: 预计 QPS 多少？

```
A: 峰值 5000 QPS。
```

**Q3**: 有安全合规要求吗？

```
A: 需要 PCI DSS 合规。
```

### 输出要点

```markdown
=== 1) 需求概述 ===
• 需求类型: API 服务
• 一句话描述: 统一支付网关，对接主流支付渠道

=== 4) 功能需求 ===
• 核心功能 (P0):
  1. 统一支付接口
  2. 微信支付对接
  3. 支付宝对接
  4. 银联对接
  5. 支付回调处理
  6. 退款功能

=== 5) 非功能需求 ===
• 性能要求:
  • QPS: 5000
  • 响应时间: < 200ms
  • 可用性: 99.95%

• 安全要求:
  • PCI DSS 合规
  • 敏感信息加密存储
  • 请求签名验证
```

## 示例 4：跳过追问模式

### 场景

你已经准备好了需求描述，不需要系统追问。

### 命令

```
/req-clarify skip-questions:true output-format:standard
```

### 输入内容

```
我要开发一个企业内部 HR 管理系统。

功能需求：
- 员工信息管理
- 考勤管理
- 薪资计算
- 绩效考核

技术要求：
- 前端：Ant Design Pro
- 后端：Spring Boot
- 数据库：PostgreSQL

非功能需求：
- 支持 500 并发用户
- 数据需要备份
- 需要 RBAC 权限控制

预计 6 个月完成。
```

### 输出

系统会直接基于提供的信息生成 9 要素结构，不进行追问。

## 示例 5：敏捷项目

### 命令流程

```
# 1. 需求澄清
/req-clarify

# 2. 使用敏捷 Backlog 模板
/req-structure template:agile-backlog

# 3. 生成文档
/doc-generator output-path:backlog/product-backlog.md
```

### 输出示例

```markdown
# 产品 Backlog

## 产品愿景
构建一个帮助团队高效协作的任务管理工具

---
```

```markdown
建议：
1. 描述 App 的主要用途
2. 说明目标用户群体
3. 列出核心功能列表

您可以：
1. 补充更多需求细节
```
