# Web 应用需求澄清示例

## 用户输入

```
我想做一个电商网站，类似淘宝那种。
```

## 对话过程

**AI**: 很好的想法！让我了解一下具体需求。

1. **业务背景**: 您的电商网站主要面向什么类型的商品？目标用户群体是什么？
2. **差异化**: 与淘宝等现有平台相比，您希望有什么特色或差异化？

**用户**: 主要卖手工艺术品，目标用户是喜欢独特手工艺品的年轻人。特色是要有艺术家故事展示。

**AI**: 明白了！手工艺术品平台，强调艺术家的故事性。继续了解：

1. **核心功能**: 最基础需要哪些功能？（如：商品浏览、购物车、下单、支付）
2. **用户互动**: 是否需要评论、收藏、关注艺术家等功能？

**用户**: 需要商品浏览、搜索、购物车、下单支付。要有艺术家主页，可以关注喜欢的艺术家。

**AI**: 收到！关于技术方面：

1. **技术栈**: 有技术栈偏好吗？
2. **预期规模**: 预计同时在线用户大概多少？
3. **上线时间**: 期望什么时候上线？

**用户**: 希望用 React + Node.js，初期预计日活 1000 左右，希望 3 个月内上线。

## 输出结果

```markdown
=== 1) 需求概述 ===
• 需求名称: 手工艺术品电商平台
• 需求类型: 新开发
• 优先级: P1
• 一句话描述: 一个专注于手工艺术品的电商平台，突出艺术家故事和作品独特性

=== 2) 业务背景 ===
• 问题陈述:
  现有大型电商平台对手工艺品的展示过于商业化，缺乏对艺术家和作品故事的呈现

• 业务目标:
  打造一个连接手工艺术家与爱好者的垂直电商平台

• 用户价值:
  艺术家获得专属展示空间，用户发现独特的手工艺品并了解背后的故事

=== 3) 目标用户 ===
• 用户画像:
  - 主要用户: 喜欢独特手工艺品的年轻人（20-35岁）
  - 次要用户: 手工艺术家创作者

• 使用场景:
  用户浏览艺术品 → 了解艺术家故事 → 购买心仪作品

• 用户痛点:
  大型平台无法深入了解艺术家背景，作品缺乏个性展示

=== 4) 功能需求 ===
• 核心功能 (P0):
  1. 商品浏览展示
  2. 商品搜索/筛选
  3. 购物车
  4. 订单下单
  5. 在线支付

• 重要功能 (P1):
  1. 艺术家主页（故事展示）
  2. 用户关注艺术家
  3. 用户收藏商品
  4. 订单管理

• 未来功能 (P2):
  1. 社区讨论区
  2. 直播展示
  3. 定制需求发布

• 功能边界:
  • 不做拍卖功能（初期）
  • 不做 C2C 二手交易

=== 5) 非功能需求 ===
• 性能要求:
  • 页面加载: < 3s
  • 并发用户: 1000

• 安全要求:
  • 支付安全: 符合 PCI DSS 标准
  • 用户数据: 加密存储

• 可用性要求:
  • 可用性: 99% 以上

=== 6) 技术约束 ===
• 技术栈:
  • 前端: React
  • 后端: Node.js
  • 数据库: 待定

• 架构要求:
  • 初期单体架构

• 集成要求:
  • 支付接口（微信/支付宝）

=== 7) 用户体验 ===
• 界面风格:
  简洁文艺，突出图片和故事展示

• 交互要求:
  流畅的购物体验，清晰的信息层级

• 响应式需求:
  支持桌面和移动端浏览器

=== 8) 验收标准 ===
• 功能验收:
  ☐ 用户可以完成完整购物流程
  ☐ 艺术家可以管理作品和故事

• 性能验收:
  ☐ 页面加载时间 < 3s

=== 9) 项目约束 ===
• 时间约束:
  3 个月内上线 MVP

• 资源约束:
  待明确

• 风险与缓解:
  • 支付接口申请: 提前准备资质材料
  • 艺术家内容获取: 建立签约激励机制
```
