# req-clarify - 需求分析助手

## 功能说明

通过智能对话将模糊的想法转化为结构化的软件需求文档。该技能会系统性地收集需求要素，输出标准化的 9 要素需求框架。

## 使用场景

- 需求不明确，需要帮助梳理
- 项目初期，进行需求收集和分析
- 准备编写需求文档前的需求澄清
- 评审需求完整性

## 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `project-type` | enum | `general` | 项目类型：web/mobile/desktop/api/general |
| `skip-questions` | boolean | `false` | 是否跳过追问，直接分析 |
| `output-format` | enum | `standard` | 输出详细程度：concise/standard/detailed |

## 使用示例

### 基础用法

```
/req-clarify
```

进入对话澄清模式，系统会根据项目类型进行系统追问。

### 指定项目类型

```
/req-clarify project-type:web
```

针对 Web 应用项目进行需求澄清（重点关注前端、响应式等）。

### 跳过追问

```
/req-clarify skip-questions:true
```

基于当前提供的信息直接分析，不进行追问。

### 详细输出

```
/req-clarify output-format:detailed
```

输出详细版需求分析，包含完整的分析过程和建议。

## 输出格式

该技能输出 9 要素需求框架：

1. **需求概述** - 名称、类型、优先级、一句话描述
2. **业务背景** - 问题陈述、业务目标、用户价值
3. **目标用户** - 用户画像、使用场景、用户痛点
4. **功能需求** - P0/P1/P2 功能分级、功能边界
5. **非功能需求** - 性能、安全、可用性要求
6. **技术约束** - 技术栈、架构、集成要求
7. **用户体验** - 界面风格、交互、响应式需求
8. **验收标准** - 可测试的完成标准
9. **项目约束** - 时间、资源、风险与缓解

## 配套技能

- `req-structure` - 将需求整理为标准 SRS 文档结构
- `doc-generator` - 生成最终的 Markdown 文档

## 使用流程建议

```
原始需求 → /req-clarify → 结构化需求要素 → /req-structure → 标准文档结构 → /doc-generator → Markdown 文档
```
